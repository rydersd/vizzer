# Ideas and article material

For each idea brought in from another project, create a Markdown brief here
before integration. Preserve the originating project's explanation, attribution
and source references, then distinguish Vizzer's adaptation rationale. A code
diff alone cannot establish an author's intent.

Copy [the template](template.md), fill what is known, and explicitly mark gaps
as **Not yet captured** and guesses as **Inference — unconfirmed**. Attach the
brief using `radar annotate --id FINGERPRINT --brief wiki/ideas/your-idea.md`.
The radar keeps the captured text, hash and revision history against that exact
proposal. Reattach after editing; edits do not silently rewrite old captures.
These wiki files belong in Git alongside the code when the change is committed.
A brief may cover several related proposals; attach it to each relevant ID.

Keep source project, author attribution when known, commit/PR/document references,
original problem, intent, choice rationale, rejected alternatives, tradeoffs,
local adaptation, evidence, outcomes, and lessons. Record failed experiments too.
Do not turn an intended benefit into a measured result. Before publishing an
article, resolve attribution, unverified claims and private source material.
